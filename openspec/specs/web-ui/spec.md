# web-ui Specification

## Purpose

Предоставляет веб-интерфейс для ввода запроса, принятия решений по предложениям агента и просмотра
результатов замера в понятном виде.

## Requirements

### Requirement: Ввод запроса

Веб-интерфейс SHALL предоставлять поле ввода SQL-запроса и список предустановленных запросов. Поле
ввода MUST быть доступно и после завершения предыдущего прогона, включая случаи отказа пользователя.

#### Scenario: Поле ввода доступно при открытии
- **WHEN** пользователь открывает интерфейс
- **THEN** отображается поле ввода запроса
- **AND** отображается список предустановленных запросов

#### Scenario: Возврат к вводу после отказа
- **WHEN** пользователь отказался от исправления запроса
- **THEN** поле ввода снова доступно
- **AND** пользователь может ввести новый запрос без перезагрузки страницы

#### Scenario: Ввод недоступен во время обработки
- **WHEN** обработка запроса выполняется
- **THEN** повторная отправка блокируется
- **AND** пользователю видно, что запрос обрабатывается

### Requirement: Отображение предложения об исправлении

Интерфейс SHALL показывать исправленный запрос и список выполненных замен, а также предоставлять
элементы управления для принятия и отказа.

#### Scenario: Показано предложение об исправлении
- **WHEN** модель исправила имена в запросе
- **THEN** интерфейс показывает исправленный запрос
- **AND** показывает, какие имена были заменены
- **AND** доступны действия «принять» и «отказаться»

### Requirement: Отображение предложения об индексе

Интерфейс SHALL показывать предложенную команду создания индекса и обоснование, а также предоставлять
элементы управления для принятия и отказа.

#### Scenario: Показано предложение об индексе
- **WHEN** модель предложила индекс
- **THEN** интерфейс показывает команду создания индекса
- **AND** показывает обоснование предложения
- **AND** доступны действия «принять» и «отказаться»

### Requirement: Отображение результата замера

Интерфейс SHALL показывать замеры до и после и вычисленную разницу. При отсутствии значимого ускорения
интерфейс MUST показывать это как равнозначный результат, а не как ошибку.

#### Scenario: Показан результат с ускорением
- **WHEN** замер после применения индекса быстрее исходного
- **THEN** интерфейс показывает обе величины и отношение ускорения

#### Scenario: Показан результат без ускорения
- **WHEN** индекс не дал значимого ускорения
- **THEN** интерфейс показывает обе величины
- **AND** явно сообщает, что ускорения нет, с указанием причины

### Requirement: Отображение предупреждений

Интерфейс SHALL показывать предупреждение, если проверка имён не выполнялась, и MUST NOT показывать
её результат как успешную проверку.

#### Scenario: Проверка имён не выполнялась
- **WHEN** модель не вызвала инструмент проверки имён
- **THEN** интерфейс показывает предупреждение о пропущенной проверке
- **AND** успешная проверка имён не отображается

### Requirement: Отображение хода длительной операции

Интерфейс SHALL показывать, что создание индекса выполняется, поскольку эта операция может занимать
заметное время.

#### Scenario: Создание индекса выполняется
- **WHEN** система применяет индекс к большой таблице
- **THEN** интерфейс показывает признак выполняющейся операции
- **AND** по завершении показывает результат
