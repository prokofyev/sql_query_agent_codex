## MODIFIED Requirements

### Requirement: Извлечение идентификаторов моделью

Система SHALL извлекать имена таблиц, их алиасы и имена колонок из текста запроса с помощью
языковой модели. Разбор SQL штатными средствами СУБД для этой цели MUST NOT использоваться.
Модель MUST NOT решать, какой таблице принадлежит колонка: принадлежность SHALL определяться
инструментом проверки по схеме базы. Имена SHALL передаваться инструменту в том виде, в каком они
записаны в запросе, включая квалификатор колонки, если он указан.

#### Scenario: Имена извлекаются из запроса
- **WHEN** пользователь отправляет корректный запрос на чтение
- **THEN** модель возвращает таблицы запроса, их алиасы и колонки
- **AND** таблицы передаются настоящими именами, без алиасов
- **AND** имена передаются инструменту в том виде, в каком они записаны в запросе

#### Scenario: Опечатки не исправляются до проверки
- **WHEN** запрос содержит имя с опечаткой
- **THEN** модели запрещено исправлять его при извлечении
- **AND** инструменту передаётся имя ровно так, как оно написано в запросе

#### Scenario: Модель не определяет таблицу-владельца колонки
- **WHEN** запрос соединяет несколько таблиц и содержит колонку без квалификатора
- **THEN** колонка передаётся инструменту без указания таблицы
- **AND** таблица-владелец определяется инструментом по схеме базы

### Requirement: Сверка имён со схемой базы

Инструмент проверки SHALL читать метаданные схемы из `information_schema` целевой базы и определять,
какие из переданных имён отсутствуют. Таблицу-владельца колонки инструмент SHALL определять
детерминированно по схеме и списку таблиц запроса: квалификатор колонки, если он указан в запросе,
задаёт владельца напрямую; иначе владельцем SHALL считаться единственная таблица запроса, в которой
такая колонка есть. Отсутствие таблицы MUST NOT отменять проверку её колонок: если для отсутствующей
таблицы есть таблицы-кандидаты, колонки SHALL проверяться по их колонкам. Если таблиц-кандидатов нет,
колонки этой таблицы не проверяются, а среди ненайденных имён остаётся только таблица. Подсказки СУБД
о похожих именах, возвращаемые в тексте ошибок, MUST NOT использоваться.

#### Scenario: Все имена существуют
- **WHEN** все переданные имена найдены в схеме
- **THEN** инструмент сообщает, что проверка пройдена
- **AND** обработка продолжается без исправлений

#### Scenario: Колонка принадлежит другой таблице запроса
- **WHEN** колонка без квалификатора есть ровно в одной из таблиц запроса, и её нет в остальных
- **THEN** инструмент считает владельцем эту таблицу
- **AND** колонка не объявляется ненайденной
- **AND** владельцем может оказаться таблица, отличная от той, с которой колонка стоит рядом в запросе

#### Scenario: Квалифицированная колонка
- **WHEN** в запросе колонка указана с квалификатором
- **THEN** владельцем считается таблица, соответствующая этому квалификатору, включая случай алиаса
- **AND** принадлежность другим таблицам запроса на результат не влияет

#### Scenario: Имя отсутствует в схеме
- **WHEN** хотя бы одно переданное имя не найдено в схеме
- **THEN** инструмент возвращает это имя среди ненайденных
- **AND** указывает, к какой таблице оно относится

#### Scenario: Опечатка и в таблице, и в колонке
- **WHEN** таблица из запроса отсутствует в схеме, для неё есть таблицы-кандидаты, и колонка этой
  таблицы не найдена среди колонок кандидатов
- **THEN** среди ненайденных имён оказываются и таблица, и эта колонка
- **AND** для каждого имени указана относящаяся к нему таблица

#### Scenario: У отсутствующей таблицы нет кандидатов
- **WHEN** таблица из запроса отсутствует в схеме и таблиц-кандидатов для неё не нашлось
- **THEN** среди ненайденных имён остаётся только таблица
- **AND** её колонки не объявляются ненайденными

### Requirement: Подбор похожих имён

Для каждого ненайденного имени инструмент SHALL подбирать похожие существующие имена и возвращать их
вместе с оценкой схожести. Поиск MUST выполняться по данным, полученным из `information_schema`.
Для колонки поиск SHALL выполняться среди колонок всех таблиц запроса. Для колонки отсутствующей
таблицы поиск SHALL выполняться среди колонок таблиц-кандидатов этой таблицы. Если ни один кандидат не
проходит порог схожести, инструмент SHALL помечать это имя как ненайденное без кандидатов и MUST NOT
подставлять замену.

#### Scenario: Опечатка в имени колонки
- **WHEN** инструмент получает имя колонки, которого нет ни в одной таблице запроса
- **THEN** он возвращает существующие имена колонок таблиц запроса, похожие на введённое
- **AND** для каждого кандидата указана оценка схожести

#### Scenario: Опечатка в колонке отсутствующей таблицы
- **WHEN** таблица из запроса отсутствует в схеме, для неё есть таблицы-кандидаты, и колонка не найдена
  среди колонок кандидатов
- **THEN** для колонки возвращаются похожие имена из колонок таблиц-кандидатов
- **AND** для каждого кандидата указана оценка схожести

#### Scenario: Похожих имён не найдено
- **WHEN** для ненайденного имени не найдено ни одного кандидата выше порога схожести
- **THEN** инструмент возвращает это имя среди ненайденных
- **AND** список кандидатов для него пуст

### Requirement: Однократное исправление запроса

Модель SHALL один раз исправить исходный запрос, опираясь на предложенных кандидатов и сведения о
неоднозначности, и только если для каждого ненайденного имени есть хотя бы один кандидат на замену.
Модель MUST NOT придумывать имена, которых нет среди предложенных кандидатов. Повторная проверка
исправленного запроса MUST NOT запускаться автоматически.

#### Scenario: Модель исправляет опечатки
- **WHEN** инструмент вернул ненайденные имена и для каждого из них есть кандидаты на замену
- **THEN** модель возвращает исправленный текст запроса
- **AND** показывает пользователю, какие имена были заменены

#### Scenario: Модель исправляет и таблицу, и колонку
- **WHEN** среди ненайденных имён есть и таблица, и колонка этой таблицы, и для обоих имён есть кандидаты
- **THEN** исправленный запрос содержит замену обоих имён
- **AND** пользователю показаны обе замены

#### Scenario: Исправление не повторяется автоматически
- **WHEN** модель выдала исправленный запрос
- **THEN** система не запускает ещё один цикл исправления
- **AND** решение передаётся пользователю

#### Scenario: Исправление не выполняется без кандидатов
- **WHEN** хотя бы для одного ненайденного имени нет кандидатов выше порога схожести
- **THEN** модель не вызывается для исправления
- **AND** исходный запрос не изменяется

## ADDED Requirements

### Requirement: Неоднозначные колонки

Если колонка без квалификатора существует более чем в одной таблице запроса, инструмент SHALL
помечать её как неоднозначную. Запрос с неоднозначной колонкой SHALL быть исправимым: исправление
состоит в добавлении к колонке квалификатора одной из таблиц, в которых она есть. В результате
проверки неоднозначная колонка SHALL отмечаться отдельным признаком, а не как отсутствующее в схеме
имя, и MUST NOT оставаться без исправления.

#### Scenario: Колонка есть в нескольких таблицах запроса
- **WHEN** колонка без квалификатора есть более чем в одной таблице запроса
- **THEN** инструмент сообщает о неоднозначности этой колонки
- **AND** в качестве исправления предлагается квалификация колонки именем таблицы, в которой она есть
- **AND** обработка не переходит к замеру

#### Scenario: Колонка есть в нескольких местах запроса
- **WHEN** неоднозначная колонка встречается в запросе несколько раз
- **THEN** сообщается о неоднозначности, относящейся к этому имени
- **AND** исправление охватывает все вхождения

### Requirement: Квалификация неоднозначной колонки моделью

Модель при исправлении запроса SHALL квалифицировать неоднозначную колонку именем таблицы, в которой
эта колонка существует в базе. Квалификатор MUST быть именем таблицы из схемы базы, а не именем
алиаса, выдуманным или несуществующим именем. Остальной текст запроса при этом MUST NOT меняться.

#### Scenario: Модель добавляет квалификатор
- **WHEN** среди ненайденных имён есть неоднозначная колонка
- **THEN** исправленный запрос содержит квалификатор этой колонки
- **AND** квалификатор указывает на таблицу, в которой колонка существует

#### Scenario: Исправление показывается пользователю
- **WHEN** модель квалифицировала неоднозначную колонку
- **THEN** пользователю показывается исправленный запрос
- **AND** решение по нему принимается на общем шаге подтверждения исправления
