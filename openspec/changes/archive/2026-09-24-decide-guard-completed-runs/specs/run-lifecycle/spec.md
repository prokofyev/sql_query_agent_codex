## Purpose

Определяет, когда прогон принимает решение пользователя: только в точке остановки, по одному решению
на этап, без повторного продолжения уже завершённого прогона.

## ADDED Requirements

### Requirement: Решение принимается только у прогона в точке решения

Система SHALL принимать решение пользователя только для прогона, который остановлен и ожидает этого
решения. Решение по завершённому прогону (в том числе завершённому отказом) и повторно отправленное
решение MUST отклоняться с сообщением о том, что прогон не ожидает решения. Состояние такого прогона
MUST NOT изменяться: отчёт остаётся тем же, повторная обработка не запускается, журнал и метрики не
пополняются.

#### Scenario: Решение по завершённому прогону отклонено
- **WHEN** клиент отправляет решение по прогону, который уже завершён
- **THEN** система отклоняет решение и сообщает, что прогон не ожидает решения
- **AND** отчёт о прогоне не изменяется

#### Scenario: Повторное решение отклонено
- **WHEN** клиент повторно отправляет решение по прогону, который уже завершился после первого решения
- **THEN** система отклоняет повторное решение
- **AND** замер, применение индекса и запись в журнал не выполняются ещё раз

#### Scenario: Неизвестный прогон остаётся неизвестным
- **WHEN** клиент отправляет решение по прогону, которого не было
- **THEN** система сообщает, что прогон не найден
- **AND** сообщение отличается от случая «прогон не ожидает решения»

### Requirement: Однократность решения при одновременной отправке

Прогон SHALL принимать не более одного решения на одну точку остановки. При одновременной отправке
нескольких решений система SHALL применить ровно одно из них, а остальные MUST отклонять так же, как
повторное решение. Замер и применение индекса MUST NOT выполняться более одного раза на одну точку
остановки.

#### Scenario: Одновременные решения
- **WHEN** по одному прогону одновременно отправлены два решения
- **THEN** ровно одно решение принимается и прогон продолжается
- **AND** остальные решения отклоняются с сообщением, что прогон не ожидает решения

#### Scenario: Побочные действия не удваиваются
- **WHEN** по одному прогону отправлено больше одного решения на одну точку остановки
- **THEN** замер запроса выполняется не более одного раза
- **AND** применение индекса выполняется не более одного раза
- **AND** в журнал добавляется не более одной записи

### Requirement: Решение относится к этапу, который видел пользователь

Решение пользователя SHALL относиться к конкретной точке остановки: запрос решения MUST называть этап,
на котором пользователь видел предложение. Система SHALL применять решение только при совпадении
названного этапа с текущим этапом остановки прогона. Решение по уже закрытому этапу MUST NOT
применяться к следующему этапу: система MUST отклонять его так же, как повторное решение. Запрос
решения без этапа MUST отклоняться как неверный.

#### Scenario: Запоздалое решение по закрытому этапу
- **WHEN** клиент отправляет решение с этапом, который прогон уже прошёл
- **THEN** система отклоняет решение и сообщает, что прогон не ожидает решения
- **AND** следующая обработка, относящаяся к новому этапу, не запускается

#### Scenario: Решение с текущим этапом
- **WHEN** клиент отправляет решение с этапом, на котором прогон остановлен
- **THEN** система принимает решение и продолжает прогон

#### Scenario: Решение без указания этапа отклонено
- **WHEN** клиент отправляет решение, не называя этап
- **THEN** система отклоняет запрос как неверный
- **AND** прогон остаётся в точке остановки и ждёт решения с указанным этапом
