## ADDED Requirements

### Requirement: Перенос принятого исправления в поле ввода

Интерфейс SHALL подставлять принятый исправленный запрос в поле ввода SQL-запроса. После принятия
исправления в поле ввода MUST находиться ровно тот запрос, который система обрабатывает дальше и для
которого предлагает индекс. Отказ от исправления, отказ от индекса и принятие индекса поле ввода
MUST NOT изменять.

#### Scenario: Пользователь принял исправление
- **WHEN** пользователь принимает предложенное исправление запроса
- **THEN** в поле ввода оказывается исправленный запрос
- **AND** поле показывает запрос целиком, включая заменённые имена

#### Scenario: Пользователь отказался от исправления
- **WHEN** пользователь отказывается от предложенного исправления
- **THEN** текст в поле ввода остаётся прежним

#### Scenario: Пользователь решил по предложению об индексе
- **WHEN** пользователь принимает или отклоняет предложение об индексе
- **THEN** текст в поле ввода не изменяется

### Requirement: Скрытие действий решения после выбора

Интерфейс SHALL скрывать элементы «принять» и «отказаться» сразу после выбора пользователя, не
дожидаясь ответа сервера, чтобы по одному предложению нельзя было решить дважды. Для нового
предложения элементы решения SHALL снова становиться доступными.

#### Scenario: Выбор сделан по предложению об исправлении
- **WHEN** пользователь нажимает «принять» или «отказаться» на предложении об исправлении
- **THEN** элементы решения по этому предложению немедленно скрываются
- **AND** повторное решение по нему недоступно

#### Scenario: Кнопки не остаются после решения
- **WHEN** предложение закрыто решением пользователя
- **THEN** интерфейс не показывает элементы «принять» и «отказаться» для этого предложения
- **AND** если система показывает следующее предложение, для него элементы решения доступны
