## MODIFIED Requirements

### Requirement: Сверка имён со схемой базы

Инструмент проверки SHALL читать метаданные схемы из `information_schema` целевой базы и определять,
какие из переданных имён отсутствуют. Отсутствие таблицы MUST NOT отменять проверку её колонок: если
для отсутствующей таблицы есть таблицы-кандидаты, колонки SHALL проверяться по их колонкам. Если
таблиц-кандидатов нет, колонки этой таблицы не проверяются, а среди ненайденных имён остаётся только
таблица. Подсказки СУБД о похожих именах, возвращаемые в тексте ошибок, MUST NOT использоваться.

#### Scenario: Все имена существуют
- **WHEN** все переданные имена найдены в схеме
- **THEN** инструмент сообщает, что проверка пройдена
- **AND** обработка продолжается без исправлений

#### Scenario: Имя отсутствует в схеме
- **WHEN** хотя бы одно переданное имя не найдено в схеме
- **THEN** инструмент возвращает это имя среди ненайденных
- **AND** указывает, к какой таблице оно относится

#### Scenario: Опечатка и в таблице, и в колонке
- **WHEN** таблица из запроса отсутствует в схеме, для неё есть таблицы-кандидаты, и колонка этой
  таблицы не найдена среди колонок кандидатов
- **THEN** среди ненайденных имён оказываются и таблица, и эта колонка
- **AND** для каждого имени указана относящаяся к нему таблица

#### Scenario: У отсутствующей таблицы нет кандидатов
- **WHEN** таблица из запроса отсутствует в схеме и таблиц-кандидатов для неё не нашлось
- **THEN** среди ненайденных имён остаётся только таблица
- **AND** её колонки не объявляются ненайденными

### Requirement: Подбор похожих имён

Для каждого ненайденного имени инструмент SHALL подбирать похожие существующие имена и возвращать их
вместе с оценкой схожести. Поиск MUST выполняться по данным, полученным из `information_schema`.
Для колонки отсутствующей таблицы поиск SHALL выполняться среди колонок таблиц-кандидатов этой
таблицы. Если ни один кандидат не проходит порог схожести, инструмент SHALL помечать это имя как
ненайденное без кандидатов и MUST NOT подставлять замену.

#### Scenario: Опечатка в имени колонки
- **WHEN** инструмент получает имя колонки, которого нет в таблице
- **THEN** он возвращает существующие имена этой таблицы, похожие на введённое
- **AND** для каждого кандидата указана оценка схожести

#### Scenario: Опечатка в колонке отсутствующей таблицы
- **WHEN** таблица из запроса отсутствует в схеме, для неё есть таблицы-кандидаты, и колонка не найдена
  среди колонок кандидатов
- **THEN** для колонки возвращаются похожие имена из колонок таблиц-кандидатов
- **AND** для каждого кандидата указана оценка схожести

#### Scenario: Похожих имён не найдено
- **WHEN** для ненайденного имени не найдено ни одного кандидата выше порога схожести
- **THEN** инструмент возвращает это имя среди ненайденных
- **AND** список кандидатов для него пуст

### Requirement: Однократное исправление запроса

Модель SHALL один раз исправить исходный запрос, опираясь на предложенных кандидатов, и только если
для каждого ненайденного имени есть хотя бы один кандидат на замену. Модель MUST NOT придумывать
имена, которых нет среди предложенных кандидатов. Повторная проверка исправленного запроса MUST NOT
запускаться автоматически.

#### Scenario: Модель исправляет опечатки
- **WHEN** инструмент вернул ненайденные имена и для каждого из них есть кандидаты на замену
- **THEN** модель возвращает исправленный текст запроса
- **AND** показывает пользователю, какие имена были замены

#### Scenario: Модель исправляет и таблицу, и колонку
- **WHEN** среди ненайденных имён есть и таблица, и колонка этой таблицы, и для обоих имён есть кандидаты
- **THEN** исправленный запрос содержит замену обоих имён
- **AND** пользователю показаны обе замены

#### Scenario: Исправление не повторяется автоматически
- **WHEN** модель выдала исправленный запрос
- **THEN** система не запускает ещё один цикл исправления
- **AND** решение передаётся пользователю

#### Scenario: Исправление не выполняется без кандидатов
- **WHEN** хотя бы для одного ненайденного имени нет кандидатов выше порога схожести
- **THEN** модель не вызывается для исправления
- **AND** исходный запрос не изменяется

## ADDED Requirements

### Requirement: Определение выполненных замен

Система SHALL определять, какие имена модель действительно заменила, по тексту исправленного запроса.
Новое имя SHALL считаться применённым по вхождению отдельным токеном, а не подстрокой: если новое имя
содержится внутри старого имени, замена MUST NOT считаться невыполненной из-за этого совпадения.
Каждая выполненная замена SHALL попадать в список замен, показываемый пользователю.

#### Scenario: Новое имя является частью старого
- **WHEN** модель заменила имя так, что новое имя содержится внутри старого как подстрока
- **THEN** замена считается выполненной
- **AND** попадает в список замен, показываемый пользователю

#### Scenario: Заменено и имя таблицы, и имя колонки
- **WHEN** модель заменила и имя таблицы, и имя колонки
- **THEN** список замен содержит обе замены
- **AND** по каждой замене указаны старое и новое имя

#### Scenario: Модель ничего не заменила
- **WHEN** исправленный запрос совпадает с исходным
- **THEN** список замен пуст
