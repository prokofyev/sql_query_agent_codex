## Why

Запрос с опечаткой и в имени таблицы, и в имени колонки исправляется лишь наполовину, после чего падает
на замере. Инструмент проверки имён обрывает проверку сущности, как только не нашёл таблицу: колонки
этой сущности не проверяются вообще, и в отчёте остаётся только имя таблицы. Модель получает одно
ненайденное имя вместо двух, чинит таблицу и оставляет битую колонку.

Пользователь видит карточку исправления с пустым списком замен и в итоге сырую ошибку СУБД вместо
исправленного запроса.

## What Changes

- Проверка имён SHALL проверять колонки отсутствующей таблицы, а не пропускать их. Пул для подбора
  берётся из колонок таблиц-кандидатов: подсказка остаётся в контексте одной таблицы и не растёт с
  размером схемы.
- Колонка отсутствующей таблицы попадает в ненайденные имена со своими кандидатами — значит модель
  правит оба имени в одном предложении, а не одно.
- Список выполненных замен SHALL определять замену по вхождению имени как отдельного токена, а не по
  подстроке: сейчас замена теряется, если новое имя содержится в старом (`sku` внутри `sku2`,
  `product_id` внутри `product_id2`), и карточка замен остаётся пустой при фактически применённой правке.
- Если для колонки отсутствующей таблицы кандидатов не нашлось, она попадает в ненайденные без
  кандидатов — и тогда работает уже существующее правило: сессия завершается с сообщением о ненайденных
  именах вместо правки половины запроса.

Вне области изменения: маппинг ошибок СУБД в понятные сообщения (при корректной правке ошибки не
возникает), отдельный статус «исправлено одно из двух имён», проверка колонок по всем колонкам схемы.

## Impact

- `src/sql_query_agent/tools/schema_check.py`: ветка отсутствующей таблицы проверяет колонки сущности
  по колонкам таблиц-кандидатов.
- `src/sql_query_agent/run/report.py`: сопоставление замен по границам идентификатора вместо подстроки.
- Карточка исправления в веб-интерфейсе показывает замену без изменений в разметке: она выводит список
  замен из отчёта, поэтому исправление сопоставления доходит до экрана само.
- Тесты: юнит-тесты проверки имён для пары «таблица + колонка», тесты сопоставления замен на подстрочных
  именах, сквозной сценарий с опечаткой в таблице и колонке.
- Схема базы, API, формат метрик и зависимости не меняются.
