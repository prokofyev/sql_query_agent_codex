## Why

Нужен сквозной учебный пример LLM-агента на LangGraph, который показывает полный цикл работы с
SQL-запросом: проверка имён по реальной схеме, исправление опечаток с подтверждением человеком,
измерение времени выполнения и проверка гипотезы об индексе с честным замером «до/после».
Существующие похожие проекты в окружении либо не измеряют время (`EXPLAIN` без `ANALYZE`), либо
не проверяют эффект индекса, либо не собирают метрики.

## What Changes

- Новый сервис: LLM-агент на LangGraph + `langchain_gigachat`, FastAPI и NiceGUI в одном процессе.
- Валидация идентификаторов: LLM извлекает имена таблиц и колонок из текста запроса и передаёт их
  инструменту `check_schema`; инструмент сверяет их с `information_schema` и подбирает похожие имена
  через `rapidfuzz`. AST для разбора SQL не используется.
- Исправление опечаток: LLM один раз правит запрос по предложенным кандидатам и показывает результат
  пользователю; пользователь принимает или отказывается и возвращается к вводу.
- Оптимизация только индексами: агент предлагает `CREATE INDEX`, инструмент применяет его в транзакции,
  повторно измеряет запрос и откатывает транзакцию, возвращая разницу.
- Набор из пяти предустановленных запросов с измеренным эффектом (ускорение от ~56x до «индекс не
  помог») плюс возможность ввести свой запрос.
- Метрики двух видов: audit-журнал замеров в схеме `metrics` базы `products` и счётчики/гистограммы
  Prometheus на эндпоинте `/metrics`.
- Человек в петле через `interrupt()`; состояние сессии хранится в `AsyncPostgresSaver` в схеме `agent`.

Вне области изменения (отложено): переформулировка запроса (rewrite), поддержка не-`SELECT` запросов,
несколько правок за один прогон, авторизация пользователей.

## Capabilities

### New Capabilities
- `query-intake`: приём SQL-запроса — библиотека предустановленных запросов и свободный ввод с проверкой.
- `schema-validation`: извлечение идентификаторов моделью, сверка с `information_schema`, подбор похожих
  имён, однократное исправление запроса и подтверждение результата пользователем.
- `index-optimization`: измерение времени выполнения, предложение индекса, применение в транзакции,
  повторное измерение, откат и вычисление разницы.
- `run-metrics`: audit-журнал прогонов в схеме `metrics` и метрики Prometheus.
- `web-ui`: веб-интерфейс NiceGUI с двумя точками решения пользователя и отображением было/стало.

## Impact

- Новый код в `src/` (граф, инструменты, LLM-адаптеры, API, UI, метрики) и `tests/`.
- База данных `products` в локальном PostgreSQL: новые схемы `agent` (checkpoint-таблицы LangGraph) и
  `metrics` (audit-журнал). Демо-данные в `public` не изменяются — откат применяется всегда.
- Новые зависимости: `langgraph`, `langgraph-checkpoint-postgres`, `langchain-gigachat`, `fastapi`,
  `nicegui`, `psycopg[binary,pool]`, `rapidfuzz`, `prometheus-client`, `pydantic-settings`.
- Требуются креденшелы GigaChat (`GIGACHAT__CREDENTIALS`).
