## Purpose

Собирает данные о прогонах: журнал замеров с результатом каждой сессии для последующего разбора и
метрики процесса для наблюдения за работой сервиса.

## ADDED Requirements

### Requirement: Журнал прогонов

Система SHALL сохранять по каждому прогону запись, содержащей исходный запрос, факт и результат
проверки имён, замеры до и после, вычисленную разницу, итоговое решение пользователя и время
завершения. Журнал MUST храниться в целевой базе данных.

#### Scenario: Прогон завершён и записан
- **WHEN** прогон доходит до сравнения до и после
- **THEN** в журнал добавляется запись с параметрами прогона
- **AND** запись содержит решения, принятые пользователем

#### Scenario: Прогон прерван пользователем
- **WHEN** пользователь отказывается от исправления или от предложения об индексе
- **THEN** в журнал добавляется запись с итогом «отклонено»
- **AND** запись содержит этап, на котором обработка остановилась

#### Scenario: Запись включает случай без ускорения
- **WHEN** прогон завершился без значимого ускорения
- **THEN** запись сохраняется как обычный результат
- **AND** факт отсутствия ускорения отражён в записи

### Requirement: Метрики процесса

Система SHALL предоставлять метрики процесса на эндпоинте `/metrics` в формате Prometheus. Метрики MUST
включать как минимум число прогонов, число применённых индексов, число случаев без ускорения и
распределение длительности замеров.

#### Scenario: Метрики доступны
- **WHEN** выполняется запрос к эндпоинту метрик
- **THEN** ответ содержит метрики в формате Prometheus

#### Scenario: Счётчики отражают прогоны
- **WHEN** прогон завершился с применением индекса
- **THEN** счётчик применённых индексов увеличивается
- **AND** счётчик прогонов увеличивается

#### Scenario: Метки не содержат текст запроса
- **WHEN** система записывает метрику прогона
- **THEN** в метках нет текста SQL-запроса и иных значений высокой кардинальности
- **AND** длительность попадает в гистограмму

### Requirement: Устойчивость журнала к недоступности

Система MUST NOT прерывать обработку запроса пользователя из-за ошибки записи в журнал; ошибка
фиксируется в логах и MUST NOT показываться пользователю как сбой обработки.

#### Scenario: Ошибка записи в журнал
- **WHEN** запись в журнал завершилась ошибкой
- **THEN** пользователю возвращается результат обработки
- **AND** ошибка фиксируется в логах
