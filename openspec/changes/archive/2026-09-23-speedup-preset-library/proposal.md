## Why

Библиотека предустановленных запросов обещает три случая ускорения, но по факту ускоряется только
один — самый простой точечный запрос. Два «ускоряющихся» примера соединений на реальных данных дают
около 1.0x и в журнале прогонов фиксируются как «без ускорения». Демонстрация ценности агента
разваливается: пользователь выбирает пример, ждёт эффекта и не получает его.

Случай «индекс не помогает» при этом остаётся нужным, но его место — свободный ввод, а не библиотека
примеров. Пресеты существуют, чтобы показать, что агент умеет находить ускорение, а не чтобы
показывать его отсутствие.

## What Changes

- Библиотека расширяется до 12 реалистичных запросов; каждый ускоряется индексом по `sku.product_id`.
  Формы разные: точечный фильтр, выборка с сортировкой и ограничением, `IN`-список, соединения по
  ключу (две и три таблицы), агрегаты и оконные функции.
- Из библиотеки убираются примеры без ускорения и вместе с ними — поле ожидаемого эффекта и
  команда индекса в описании пресета. Пресет становится чистым текстом запроса с подписью и
  пояснением.
- Поведение «индекс не помогает» для свободного введённого запроса сохраняется без изменений:
  агент по-прежнему честно сообщает об отсутствии ускорения и его причине.
- Появляется интеграционная проверка, что каждый пресет на реальной базе действительно ускоряется
  индексом; раньше такого контроля не было, поэтому библиотека и разошлась с реальностью.

Вне области изменения: логика графа и агента, промпты модели, алгоритм подбора индекса моделью,
журнал, метрики, обработка случая «без ускорения».

### Modified Capabilities
- `query-intake`: требование о предустановленной библиотеке заменяется. Прежнее требование
  (не менее пяти запросов, из них минимум два без ускорения, с описанием ожидаемого эффекта)
  удаляется как противоречащее цели; вместо него вводится требование о библиотеке из 12 реалистичных
  запросов, каждый из которых ускоряется индексом. Сценарий «индекс не помогает» уходит из библиотеки
  и остаётся только для свободного ввода в требовании `index-optimization`.

## Impact

- `src/sql_query_agent/presets.py`: новый состав библиотеки; из модели пресета убираются ожидаемый
  эффект и команда индекса, вместе с перечислением эффектов и вспомогательными выборками.
- `src/sql_query_agent/api/schemas.py`: из схемы пресета убирается поле ожидаемого эффекта.
- `src/sql_query_agent/api/routes.py`: без изменений кода, меняются только данные `/presets`.
- `tests/test_presets.py`, `tests/test_api.py`: проверки состава и валидности библиотеки.
- `tests/test_end_to_end.py`: идентификаторы пресетов в сквозных сценариях; сценарий «без ускорения»
  переходит на свободный ввод.
- `tests/test_schema_invariance_integration.py`: команда индекса берётся из константы теста, а не из
  пресета.
- Новый интеграционный тест: каждый пресет ускоряется на реальной базе.
- `README.md`: убирается утверждение, что библиотека содержит случаи без ускорения.
- Контракт `/presets` теряет поле `expected`: внешние клиенты, разбирающие его, должны это учесть.
