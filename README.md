# SQL Index Advisor

LLM-агент на LangGraph: проверяет имена таблиц и колонок в SQL-запросе по реальной схеме
базы, исправляет опечатки с подтверждением человеком и проверяет гипотезу об индексе —
создаёт индекс в транзакции, повторно замеряет запрос и откатывает транзакцию.

## Что делает

1. Модель извлекает из запроса имена таблиц и колонок и передаёт их инструменту `check_schema`.
2. Инструмент сверяет имена с `information_schema` и подбирает похожие через `rapidfuzz`.
3. При опечатках модель правит запрос, а пользователь принимает или отклоняет правку. Если похожих
   имён не нашлось и заменять нечем, система сообщает, какие имена не найдены, и завершает сессию —
   модель ничего не придумывает, замер не выполняется.
4. Запрос замеряется в read-only транзакции: прогрев, несколько повторов, медиана.
5. Модель предлагает `CREATE INDEX`; при согласии инструмент создаёт индекс в транзакции, повторно
   замеряет запрос и откатывает транзакцию. База остаётся в исходном состоянии.
6. Итог прогона пишется в audit-журнал схемы `metrics`, а счётчики и гистограммы отдаются на
   `/metrics` в формате Prometheus.

Библиотека предустановленных запросов берётся из внешнего файла `resources/presets.yaml` (путь
задаётся настройкой `SQA_PRESETS__PATH`). В ней двенадцать реалистичных примеров — от точечного
фильтра и страницы с сортировкой до соединений, агрегатов и оконных функций, — и разные пресеты
ускоряются индексами по разным колонкам демо-базы: `sku(product_id)`, `sku(product_size_id)`,
`sku(added_at)` и `product(brand_id)`. Отсутствие ускорения тоже полноценный результат, а не ошибка:
если ввести свой запрос, которому индекс не помогает (например, фильтр по низкоселективной
колонке), агент честно сообщит об этом и укажет причину.

Библиотека не зашита в код: отсутствующий или пустой файл даёт пустую библиотеку, и приложение
продолжает работать. Повреждённая запись (нет `id`, `title` или `sql`) — ошибка загрузки, а не
повод показать пользователю неполный запрос.

## Демо-данные

Файл пресетов описывает запросы под конкретную форму локальной демонстрационной базы `products`.
Наполнение разовое и в репозиторий не кладётся; справочный SQL и обоснование — в
`openspec/changes/archive/2026-09-24-demo-data-and-preset-yaml/design.md`. Форма, на которой
библиотека показывает разные индексы:

| Таблица | Строк | Что даёт |
|---|---|---|
| `brand` | 1 000 | индекс по `product.brand_id` |
| `product` | 20 000 | `brand_id` → 1 000 различных значений |
| `product_size` | 50 | индекс по `sku.product_size_id` |
| `product_color` | 2 | демонстрация «индекс не помогает» |
| `sku` | 100 000 | `product_id` и колонка `added_at` со разбросом на два года |

Пресеты демонстрационные: на чужой базе они остаются валидными, но индекс может их не ускорять —
для чужой схемы предназначен свободный ввод. Отсутствие `sku.added_at` или малое число значений
`sku.product_size_id` означает, что интеграционные проверки обещания библиотеки пропускаются,
а не падают.

## Схема базы в интерфейсе

Вверху страницы `/ui/`, перед полем ввода, показывается панель схемы базы: таблицы со столбцами,
связи между таблицами и число строк у каждой таблицы. Схема нарисована в псевдографике и хранится
готовым текстом в файле `resources/schema.yaml` (путь задаётся настройкой `SQA_SCHEMA__PATH`).

Число строк — статичный снимок на момент заливки демо-данных, а не живое значение из базы: схема не
запрашивается у СУБД. При перезаливке данных или смене базы файл перерисовывают вручную — рисунок
правится прямо в YAML.

Схема необязательна: отсутствующий или пустой файл означает «схемы нет», панель не показывается, а
интерфейс работает как обычно. Повреждённый файл (нет поля `diagram`) даёт ошибку загрузки, а не
частичный рисунок.

## Требования

- Python 3.13+, [uv](https://docs.astral.sh/uv/).
- Локальный PostgreSQL с базой (для демо-пресетов — `products` с таблицами `brand`, `product`,
  `sku`, `product_size`, `product_color`) и ролью с правом `CREATE` в ней.
- Креденшелы GigaChat для обращений к модели.

На произвольной базе агент тоже работает: демо-пресеты — необязательный файл, а фильтр по
низкоселективной колонке своего запроса показывает ветку «индекс не помогает».

## Настройка

```bash
uv sync
cp .env.example .env
```

Заполните `.env`:

- `SQA_DATABASE__DSN` — строка подключения к базе `products`;
- `SQA_GIGACHAT__CREDENTIALS` — ключ авторизации GigaChat;
- при необходимости `SQA_GIGACHAT__VERIFY_SSL=false` для локального стенда и
  `SQA_GIGACHAT__MODEL` для выбора модели;
- при необходимости `SQA_PRESETS__PATH` — путь к библиотеке пресетов (по умолчанию
  `resources/presets.yaml`);
- при необходимости `SQA_SCHEMA__PATH` — путь к схеме базы для панели интерфейса (по умолчанию
  `resources/schema.yaml`).

Схемы `agent` (checkpoint'ы LangGraph) и `metrics` (журнал прогонов) создаются автоматически при
запуске; демо-схема `public` не изменяется.

## Запуск

```bash
uv run sql-index-advisor --host 127.0.0.1 --port 8080
```

- Веб-интерфейс: `http://127.0.0.1:8080/ui/`
- API: `POST /runs`, `POST /runs/{thread_id}/decision`, `GET /runs`, `GET /runs/{thread_id}`,
  `GET /presets`, `GET /schema`, `GET /metrics`, `GET /healthz`

## Тесты

```bash
uv run pytest -q                  # быстрые тесты без базы и модели
uv run pytest -q -m integration   # тесты на локальной базе products
uv run pytest -q --run-llm        # тесты с реальной моделью GigaChat
uv run ruff check src tests
```

Интеграционные тесты пропускаются, если база недоступна, а тесты с моделью — без флага `--run-llm`.
